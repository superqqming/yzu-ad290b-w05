AD290B · W05 · AI 平台比較

AI 平台怎麼選：對話、執行、比較與驗證

同一題、同一輸入、同一驗收。工具不同，判準不變。

本課任務定位，不是能力排名。

01

先分清三種工作面

同一個生態通常同時有「談」的介面和「做」的介面；第三面是人。分清楚這三面，才知道一句「AI 做好了」實際代表什麼。

對話面

理解問題、討論、形成規格。

執行面

在明確授權的環境中讀寫檔案、執行與測試。

驗收面

人開啟真實成果、重跑同一組檢查，並決定是否採用。

「平台回報完成」不等於「成果正確」。只有驗收面通過，這件事才算完成。

02

我現在要做什麼？

選一個目前的情境。結果只會告訴你該用哪一個工作面、要留下什麼證據、以及行不通時怎麼辦；不會告訴你哪個平台比較好。
適合的工作面
對話面。重點是把需求談清楚，寫成 brief.md。
必須保存的證據
brief.md 本身：目標、輸入與來源、必要輸出與正式位置、限制、驗收條件、回報位置。
行不通時
寫不出驗收條件，就表示需求還沒想清楚。先補驗收條件，不要先叫平台開工。
適合的工作面
執行面，而且要先確認你真的有一個被授權的執行環境。
必須保存的證據
實際產物的完整路徑、實際跑過的檢查與輸出、未完成與限制。
行不通時
沒有執行環境就只能標記為「草稿／未實測」，不可寫成已完成。
適合的工作面
另一個平台的對話面或執行面，用同一份輸入包重做一次。
必須保存的證據
兩邊各自的 report.md 與產物，以及同一組驗收案例的結果。
行不通時
不要為了遷就第二個平台而重寫題目。題目一改，比較就失效。
適合的工作面
先退回對話面，把已經做到的部分固定下來。
必須保存的證據
brief.md、最小範例、錯誤案例與驗收條件；不要只複製整段聊天紀錄。
行不通時
不能上傳檔案時，可以討論文字規格，但不得宣稱已讀檔或已驗證實際成果。
03

三個平台生態

三欄等寬、同一組欄位，順序不代表名次。每一欄描述的是本課任務中的用法，不是產品總評。

ChatGPT／Codex

對話面
在 ChatGPT 對話中整理需求、討論規格，並閱讀你實際上傳的檔案。
執行面與授權邊界
Codex 是執行面，只在你明確授權的工作區或環境中讀寫檔案、執行與測試。官方說明 Codex 包含在各個 ChatGPT 方案（含 Free 與 Go），但可用額度依方案而異；在雲端執行任務的 Codex Cloud 則「不包含 Free 與 Go」，且仍受推出進度與工作區設定影響。
本課定位
討論、整理需求、寫任務書與驗收。
檔案能見範圍
對話面看得到你實際上傳的檔案；執行面只看得到被授權的那一個工作區。
應保留的證據
對話紀錄、brief.md、執行與變更紀錄。
免費帳號／教室現場備援
學校或公司帳號可能由管理者決定能否使用雲端任務，部分席次類型無法建立雲端環境。先用自己的帳號登入，確認畫面上實際有什麼。

實際可用功能 ＝ 介面 × 帳號方案 × 權限 × 當下環境。

Claude／Claude Code

對話面
在 Claude 對話中理解與改寫文件，也可閱讀你上傳的檔案。
執行面與授權邊界
Claude Code 是終端機或 IDE 的執行面。官方說明列出的取得方式是付費個人方案、組織席次（能否使用由席次類型與管理者設定決定），或以開發者主控台／API 授權登入；官方頁面沒有列出免費帳號的路徑。
本課定位
讀檔、實作與測試。
檔案能見範圍
對話面只看得到你上傳的檔案。對話中產生的檔案放在 claude.ai 的沙盒環境，與你的系統分開，要下載或存到雲端硬碟才會到你手上——這不等於已經改到你電腦裡的專案。
應保留的證據
對話紀錄、任務書、實際檔案與測試輸出。
免費帳號／教室現場備援
官方把對話中的程式執行與檔案建立列為各方案皆可用（含免費），但它由設定中的開關控制，受管理的團隊帳號可由擁有者關閉，而且會消耗你自己方案的額度。

實際可用功能 ＝ 介面 × 帳號方案 × 權限 × 當下環境。

Gemini Apps／執行環境

對話面
Gemini Apps 可以附加檔案；電腦版網頁另可匯入一個程式碼資料夾或一個 GitHub 儲存庫讓它分析。
執行面與授權邊界
本課不預設你有可用的 Gemini 執行面。Google 官方文件說明：自 2026-06-18 起，Gemini Code Assist 的 IDE 擴充功能與 Gemini CLI 已停止服務個人版與一般消費者訂閱層級；Standard 與 Enterprise 訂閱不受影響。
本課定位
用同一份輸入做獨立嘗試與比較。
檔案能見範圍
看得到你上傳或匯入的那一份。使用學校或公司的 Google 帳號時，從雲端硬碟上傳需要機構管理者先開啟權限。
應保留的證據
對話紀錄、任務書、你自己存下來的檔案。
免費帳號／教室現場備援
需要修改實際專案並重跑測試時，由人把同一份輸入包交給確實可用的執行環境，不要假設 IDE 擴充功能或命令列可用。

實際可用功能 ＝ 介面 × 帳號方案 × 權限 × 當下環境。

04

免費帳號決策路徑

先以自己的帳號確認功能、額度與權限，再決定這一步要在哪裡做。

只需要討論或整理規格

用目前能接收必要資料的對話面就夠了。先把 brief.md 寫完整，再談要不要動手。

必須修改實際檔案並跑測試

先確認你真的有一個被授權的執行環境。沒有的話，只可以標記為「草稿／未實測」，不得寫成已完成。

需要第二意見

把同一份輸入包交給另一個平台，不重新改寫題目。題目一改，兩邊就不能比較。

額度已滿

保存 brief.md、最小範例、錯誤案例與驗收條件，交接到另一個可用平台；不要只複製整段聊天紀錄。

無法上傳檔案

可以討論文字規格，但不得宣稱已讀檔或已驗證實際成果。把尚未驗證的部分明寫出來。

05

Markdown 跨平台交接閉環

Markdown 是可攜式純文字，任何平台都打得開，可以保存標題、清單、完整路徑與驗收條件。

  1. 1
    討論
  2. 2
    brief.md
  3. 3
    人工啟動另一平台執行
  4. 4
    report.md＋產物＋證據
  5. 5
    人開啟成果並驗證
  6. 6
    修正再執行

儲存 Markdown 不會通知另一個 AI；下一次交接仍由人啟動。

brief.md 模板 
# brief.md

- 任務編號：T0xx / R01
- 目標：
- 輸入與來源：
- 必要輸出與正式位置：
- 限制／禁止改動：
- 驗收條件：
- 回報位置：
report.md 模板 
# report.md

- 實際產物與完整路徑／連結：
- 實際執行的檢查與結果：
- 已知缺口與未完成：
- 未改動項目：
- 仍需人工驗證事項：
06

同一驗收門

三個平台交回來的東西，只比較這五類證據，不看誰講得比較有自信。

01
是否正確重述規格
02
是否使用指定輸入
03
是否有可開啟的實際產物
04
是否列出未完成與限制
05
是否通過同一組驗收案例
把原則變具體：W05 小型投影工具的驗收案例
  • 用同一個不對稱物件驗收。對稱物件換角法看不出差別，等於沒測。
  • 切換第一角法與第三角法時，側視圖必須換到正視圖的另一側。
  • 視圖要對齊，不是擺在旁邊就算。
  • 不得鏡像。換角法改變的是視圖位置，不是把圖翻面。
  • 資訊不足時不得猜唯一解；結果可能是無解、唯一解或多解。

通過列出的測試，未測範圍仍然未知。通過部分測試不等於整張圖面正確。
